# Memory

These files are the project’s memory. They exist so a new chat can catch up without re-deciding things we already settled.

Read in this order at the start of every session:

1. [task.md](../task.md) — what to do next.
2. [decisions.md](decisions.md) — choices already made. Do not reopen one unless Brandon asks.
3. [open-questions.md](open-questions.md) — ask at least one of these during the session, even in the middle of other work.
4. [log.md](log.md) — what happened last time.
5. [PLAN.md](../PLAN.md) — the full product plan, when you need the detail.

## What each file is for

| File | What goes in it | What stays out |
| --- | --- | --- |
| `../PLAN.md` | What we are building and why | Daily checkboxes |
| `../task.md` | Ordered work, checked off as we go | Long explanations |
| `decisions.md` | A choice and the reason, in a few lines | Ideas we have not picked |
| `open-questions.md` | Anything we still need to ask Brandon | Settled answers |
| `log.md` | One short entry per work session | The plan itself |

## Rules

- Brandon is a beginner coder and a cybersecurity professional. Explain a new file in plain language: what it is, why it exists, and what it does.
- Ask questions any time, including mid-task. Add new questions here the moment they come up. When he answers, move the answer to `decisions.md` and remove it from this question list.
- Never put API keys, passwords, or form secrets in these files.
- The website code does not start until Brandon says to build.
